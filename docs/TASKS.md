# Smart Resume 0.1.0 task scope

Requested outcome: an inspectable and reusable local skill project and download
package before deciding whether to create a separate Repo Standards Skill.

| Requirement | Implementation |
| --- | --- |
| Installable skill | SKILL.md and scripts/install.py |
| Three-language navigation | README.md, README.zh-TW.md, README.en.md |
| JD screenshot workflow | Host vision procedure in SKILL.md |
| Reuse authorized history | Host memory/material inventory, then old resume if insufficient |
| Ask missing items individually | Intake order and photo provide/omit decision |
| Single intention | Exact jd.title equality validation |
| Truth and sources | Claim eligibility, source ledger, private gap handling |
| PDF + editable output | ReportLab PDF and editable HTML from common JSON |
| Default two A4 pages | Two-page intake; explicit one-page support; overflow refusal |
| Templates and scripts | Intake/HTML assets, render/install/package commands |
| Basic tests | Evidence, escaping, overflow, PDF, installation and packaging |
| Privacy | Synthetic examples, private inputs outside repo, allowlisted package |
| GitHub readiness | AGENTS, contribution/license/version/changelog, CI and PR template |

Outside this delivery: building a Repo Standards Skill, actual applications,
GitHub creation/push, public hosting, automatic memory/OCR services, DOCX export,
global installation without a chosen target, or a real candidate resume.

The local fixture installation proves copying and completeness, not native
discovery by every agent. Host acceptance requires loading and invoking the
installed skill in that host. Remote CI requires a later authorized push.
