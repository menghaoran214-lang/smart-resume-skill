# Security and privacy

Do not attach real resumes, photos, phone numbers, addresses or private source
documents to issues or pull requests. Use fictional examples with the same
structure when reporting a problem.

For a vulnerability or accidental personal-data exposure, use the repository's
Security → Report a vulnerability option when available. If private reporting
is unavailable, contact the repository owner through an existing private
channel. Do not publish exploit details or sensitive data in a public issue.

Reports should include the affected version, reproduction steps using fictional
data and the expected behavior. No response deadline or supported-version
commitment is currently offered.
